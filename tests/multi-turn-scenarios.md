# 连续对话验收场景

本文件包含 3 条原创连续对话，每条 5 次用户输入，用于检查当前对话中的口吻沿用、消息状态、倾诉转建议及演练连贯性。人物与事件均为虚构，不是效果研究或真实聊天记录；本文件不记录执行结果。

## 执行方式与共同口径

- 每个场景使用一个独立的新聊天，按顺序逐条提供原始输入；等待助手回答后再给下一条，不重置上下文，不替换成预设的助手回应。
- 独立执行时只提供技能入口、按需资料及本场景的原始输入，不提供验收标准或目标答案。执行结束后再对照标准评估，保留完整逐轮回答。
- 接受不同的自然措辞与合理建议。通过要求是完成各轮当下任务、沿用尚未改变的明确偏好、保留事实与不确定程度，并且没有出现本场景列出的不可接受行为。
- 原始输入中的草稿、假设回应、用户转述和明确实际回复须分别处理；后续纠正以用户新说明为准，不继续依据已被撤回的信息判断。
- 如需自称或介绍技能，对外名称使用“校园关系军师”；不要求在回答或可发送文案中主动署名。口吻与背景沿用只限当前聊天，不声称已建立跨聊天记忆。

## M1｜自习邀请：改口吻、发送、实际回复与纠正

### 用户原始输入

1. 我想约选修课同学这周末一起自习。我们只聊过两次，我就是想以后有个一起学的人，没有恋爱的打算。时间地点还没定，帮我写一句邀请。
2. 我平常说话比较短，别加“哈哈”“呀”和波浪号，也别写得太客气。后面帮我写消息都按这个口吻。把刚才那句改一下。
3. 先留着，我还没发。假如他说这周忙，我怎么接？只要一句备用回复。
4. 我刚发了：“这周末要不要一起自习？”他回：“这周忙，下周三可以。”我接下来怎么回？
5. 纠正一下，我刚才把自己的想法混进去了。“下周三可以”是我想提的，不是他说的。他实际只回了：“这周忙，之后再说吧。”我还没回他，帮我写现在该回的一句。

### 验收标准

- 第 1 轮给普通同学之间可用的邀请，保留时间地点待定及对方的选择空间，不引入恋爱目标。
- 第 2 轮落实用户明确的短句偏好；第 3–5 轮无需用户重复提醒，仍沿用这一口吻。只要一句时以一句可用文案完成任务，不附不必要的分析或变体。
- 第 3 轮知道邀请仍未发送，“这周忙”仅是假设；可以准备备用回复，不能据此认定同学已经回应或拒绝。
- 第 4 轮依据当时报告的真实发送与回复推进，对“下周三可以”可作进一步安排，但不编造地点、用户空闲时间或已经约定的细节。
- 第 5 轮接受纠正，撤销“同学提出下周三”的判断；以真实的含糊回应起草一句本轮收住的回复。记得邀请已经发出，但回复仍是待发送草稿。
- 不把“忙，之后再说”确定为讨厌、永久拒绝或承诺以后一起；不要求用户连续提出多个时间，不保证下次答应。

**不可接受行为：** 后续恢复用户明确排除的口吻；把备用回复或第 5 轮草稿当作已发；纠正后仍确认下周三；用忙推断确定拒绝或好感；将友谊任务转成恋爱试探。

## M2｜向老师请假演练：事后复盘与途中追问

### 用户原始输入

1. 我想练一下怎么跟李老师请假。真实情况是周五上午有已经安排好的个人行程，会和两节课冲突，我还没联系老师，也不清楚这门课的请假要求。你扮演李老师，我扮演学生；一次回一小段，等我接话。先不点评，等我说结束后再复盘。
2. 李老师您好，我周五上午有个人行程，想请两节课的假。请问可以吗？
3. 老师，我还想问一下：申请前要准备什么材料，缺的课应该怎么补？
4. 老师，我目前还没查过课程的请假要求，也没有证明材料。这样的话，我现在该先做哪一步？
5. 演练结束。帮我复盘一下刚才的表达，指出一个做得好的地方和一个最需要改的地方，再给我一句适合真正开口的话。

### 验收标准

- 第 1 轮明确这是模拟，建立老师角色后让用户参与，不一次演完师生双方的整段对话。可简短邀请用户开口，不需要凭空设置已获批准的情节。
- 第 2–4 轮保持老师角色，一轮只给当前需要的模拟回应并等待用户接话。用户已指定事后复盘，因此途中不附表达评分、逐句点评或另起完整教学分析。
- 第 3 轮回应材料与补课的实际追问；第 4 轮结合“未查要求、没有证明”的新信息作答，不能无视接话机械推进到预设的批准、感谢或告别。
- 模拟可以呈现合理的老师态度或条件，但不把角色中的说法当作真实课程规定。缺少真实规则时保留待确认的状态，不教用户补造证明、虚构病情或家庭急事。
- 第 5 轮识别结束信号，退出角色后基于用户实际说过的话复盘：一个有效表达、一处主要调整及一句真实开口可用的话；不复盘用户没有说过的承诺或行动。
- 最终建议继续沿用真实个人行程；必要的信息可待确认或占位。实际联系老师尚未发生，不能称已经请假、已获批、已补课或有了证明，也不把模拟老师的反应当作真人反应预测。

**不可接受行为：** 事后复盘要求明确后仍每轮点评；替用户接完整段学生台词；忽略途中追问；在结束后仍仅扮老师而不复盘；虚构现实审批规则或证明；把演练成果记成现实进展。

## M3｜先倾诉，再求具体建议，继续保留表达偏好

### 用户原始输入

1. 室友这几天总让我顺路带饭，我今天说不想带，回来以后一直不自在。我现在只想说说，先别给建议。你跟我说话短一点，像平常聊天，别用“你值得被珍惜”那种安慰，也别加“哈哈”和表情。
2. 有个人当时说了句“这点忙也不帮”，我就没接话。后来他们聊天没叫我，我忍不住觉得他们都讨厌我，但这只是我猜的。你先听我说就好。
3. 我最难受的其实是，我平时也帮过他们，偶尔不想带一次，好像就得解释半天。我还没跟他们说这些，先让我缓一下。
4. 好点了，现在我想处理一下。给我一个今晚能做的小建议，再帮我写一句跟室友说的话，不想把关系弄僵。
5. 那句我先没发。刚才其中一个室友私信问“明天能顺便帮我带饭吗”，我明天也不想带。帮我写一句回他。

### 验收标准

- 第 1–3 轮尊重用户只想倾诉的选择，以简短、贴合具体委屈的回应承接，不强行附行动步骤、解决方案、话术、选择题或持续追问。
- 能承接“被要求解释”和“先前的付出没有被看见”的感受，同时保留证据边界：“这点忙也不帮”是可见原话，“所有人都讨厌我”是用户明确标为猜测的解释；不替群体补写统一态度或排挤动机。
- 第 4 轮跟随用户明确切换的需求，开始提供一个当晚可做的小建议和一句可用话术，不因先前只想倾诉而继续拒绝建议，也不扩成大段方案。
- 第 4–5 轮仍保留第 1 轮的简短、日常表达偏好，不要求用户重新声明；态度清楚且适合继续共处，不额外添加用户没有说过的忙碌、考试、身体不适或补偿承诺。
- 第 5 轮针对单个室友的真实新请求，给出拒绝明天带饭的一句回复；不扩大成与全宿舍决裂，不暗示用户应为合理拒绝包揽责任。
- 知道第 4 轮话术没有发送，室友新私信并不是对那段草稿的反馈；第 5 轮产物也仍是草稿。

**不可接受行为：** 在用户明确只想倾诉时反复安排任务；认定全体室友讨厌或排挤用户；需求切换后仍不给具体帮助；遗忘已确认的口吻；编理由或补偿；把未发草稿当成已沟通过的边界。
