# 狗头军师·校园版 v0.1 实施计划

日期：2026-10-03。基于[已定设计](../specs/2026-10-03-campus-relations-design.md)。用户明确要求按方案实施；使用 Codex 原生规划并在本聊天执行并行分工。

## 1. 固定来源与许可

- 固定上游 commit `6db7354a4002dc7c448a9c87ffdad8132570c9d3`，读取核心流程、元数据、校验和 MIT 许可。
- 保留原版权及许可，记录继承、重写、暂缓机制。
- 原版快照存于开发资料区，不进入运行包。

## 2. 编写运行内容

- 主代理编写 `SKILL.md` 和 `agents/openai.yaml`，标识统一为 `campus-relations`。
- 并行编写师生、同学、修复三个 practical 文件，提供原创话术和场景判断。
- 并行编写 evidence 文件，只做简短转述、出处与限制记录。
- 审核所有 runtime 引用，保持按需加载；首版不加入记忆功能。

## 3. 实现分发工具

- 实现无额外依赖的 Python 校验器，检查入口、元数据、运行路径、大小和项目分发文件。
- 实现本地安装器，默认识别 `CODEX_HOME/skills`，否则使用用户目录 `.codex/skills`。
- 仅复制 `SKILL.md`、`agents/`、`references/`、`scripts/` 及许可归属文件；安装前后验证，已有目标拒绝覆盖。
- 为工具运行、文件缺失、路径越界与安装冲突写实际故障测试。

## 4. 行为演练与修订

- 写 20 个原创场景及评分规则：12 日常、4 修复、4 边界。
- 独立代理读取成品技能与相关参考，完成全部场景；保存回答和按规则评判。
- 主代理复核关键行为，依据发现修正；修正涉及场景重新演练。
- 明确报告这些演练的范围，不宣称已验证真实关系改善。

## 5. 完成交付

- 写 README、原创演示、来源记录和验证报告。
- 运行技能创建工具的 `quick_validate.py`（环境具备其依赖时）、项目校验和工具单元测试。
- 安装到本机技能目录；目标若已存在则保留，不覆盖。
- 在独立项目目录建立本地 Git 仓库并记录初始提交；若机器无 Git 提交身份则保留可提交文件，不改全局配置。
- 打开 README，交付可调用名称、项目路径、测试结论和远程发布状态。

## 检查命令

在项目目录运行：

```text
python scripts/validate_skill.py . --project
python -m unittest discover -s tests -p test_*.py
python scripts/install_skill.py
```

工具测试只在临时目录内改写文件。行为报告须注明评估方式和执行日期，失败项修正后保留前后依据。
