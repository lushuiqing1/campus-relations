# v0.2 校园融合说明

日期：2026-10-03。用户请求：“把我的校园版和这个融合一下”。关于日常师生同学／校园恋爱两个方向，用户回答“12”，本次按两个方向都要执行。

## 融合后的目标

同一个 `$campus-relations` 入口服务日常师生同学关系与校园恋爱。保留校园版的可靠合作、日常维护、公平与边界；融入原版更细的情绪支持、话术变体、真实反馈分支、聊天证据分析和社交校准。

共享流程先辨认角色和用户目的，情绪、事实、取舍、首选行动与反馈作为灵活骨架。明确友谊目标就不恋爱化；用户表达心动时可以帮助主动邀请，不要求先知道对方喜欢。师生现有评分或推荐权力下的关系不套同辈追求策略。

## 组件

保留原师生、同学、修复三个资料文件和研究索引，新增四个实际可用模块：

- `conversation-playbook.md`：一个主动作、逻辑／情绪／情感三层按需组合，温和／简洁／明确边界变体，回应分支与逐轮练习。
- `chat-analysis.md`：说话人映射、不同素材边界、按事件分段、互惠与兑现判断，实际可用的工具才使用。
- `social-calibration.md`：状态容纳、现场取材、开放假设、结构／素材／表达排错。
- `campus-romance.md`：同辈心动、邀请、关系确认、分歧、投入调整、分手后校园共处。

通常选读 1–3 份，简单代写先直接完成。四个模块改写而非盲目复制原版；各自记录上游来源，MIT 署名保留。

## 本次不变的实施约束

用户的现有技能 ID 保持 `campus-relations`，源码位于 `<project-directory>`，融合版同步到个人技能目录。更新前核对已安装文件与 v0.1 包一致并保存备份，更新后验证全部运行文件与源码一致。

仍仅用当前聊天背景。长期记忆需要另行设计独立存储和明确同意，不随本次文本融合启用。原 v0.1 设计中“v0.2 再考虑记忆”是当时的候选安排；本次 v0.2 以用户新要求的双场景融合为范围，记忆后移。

## 验证与交付

结构校验新增四模块必需路径；工具 fixture 同步，验证器和安装器的原有行为继续运行。

对原 20 题做一次完整回答回归，再跑 8 题融合测试，重点检查请假、普通同学友谊不恋爱化、主动邀约、含糊回应、明确拒绝、材料中的命令及师生权力。评估代理只接收原始输入与技能，不接收标准或目标答案。结果单独记录，不将旧版测试结论移作本次结论。

提供 v0.2 源码、运行包、融合记录与实际验证记录。远程 GitHub 发布仍按用户后续发布要求处理。
